# Design decisions

This file records the decisions made while building Tervic, what was verified against each
framework's current API, and the measured performance numbers. Newest sections are at the end.

## 1. Framework APIs verified (2026-11-20)

Everything below was checked against the installed package source, not from memory.

## 2. Product and packaging

- **PyPI name:** `tervic` was available (HTTP 404 on `https://pypi.org/pypi/tervic/json` on 2026-11-20), so the distribution and import name are both `tervic`.
- **Core dependencies:** `pydantic`, `typer`, `rich`, plus `tomli` on Python 3.10 only (the standard library `tomllib` exists from 3.11). Everything else is an optional extra imported lazily.
- **IDs:** run and step IDs are ULIDs generated by Tervic itself (no dependency): 48-bit millisecond timestamp + 80 random bits, Crockford base32. They sort by creation time.

## 3. Safety ("never break the agent")

- Every recorder, adapter callback, detector and exporter entry point goes through `tervic.core.safety`. An internal error is logged once per location at WARNING level on the `tervic` logger and then swallowed. The user's function is always called exactly once with the original arguments, and its return value or exception passes through unchanged.
- The decorator wraps the user's call, never the other way round: Tervic code runs before and after the call inside its own `try` blocks, so a Tervic failure cannot skip or repeat the user's function.

## 4. Recording and storage

- **Tail-based sampling in prod.** Events for a run are buffered in memory (max 10,000 per run; extra events are dropped and counted). At run end the background writer analyzes the run; it keeps the run if it crashed, has an error-severity finding, or falls inside `sample_rate`. In `dev` and `ci` every run is kept and events are also streamed to disk as they happen, so a hard crash still leaves a partial `events.jsonl`.
- **Write queue.** One background daemon thread owns all disk writes through a bounded queue of 10,000 items. When the queue is full: `prod` drops and counts; `dev`/`ci` waits at most 50 ms, then drops and counts.
- **When analysis runs.** In `prod` it runs in the background thread after the run ends and never in the request path. In `dev`/`ci` the end of `tervic.run(...)` waits for the writer to finish analyzing (bounded at 30 s) so `run.verdict` and `tervic check` see the result immediately.
- **SQLite index.** Each operation uses a short-lived connection, so there is no shared connection across threads.

## 5. Privacy

- Redaction runs on every snapshot before it is buffered, written or exported. The replacement is `[REDACTED:<type>:<first 8 hex of sha256>]`, so two equal secrets still compare equal and TV501 can tell that a secret reached an LLM without storing it.
- Pure hexadecimal strings are never treated as high-entropy secrets, because Tervic itself stores sha256 digests of truncated values.
- Placeholders (`YOUR_API_KEY`, `<token>`, `xxx`, `changeme`, `example...`, `${VAR}`, `***`) are never redacted.

## 6. Replay

- **No pickle.** Cassettes store exact values only for types that round-trip safely: JSON-native values, pydantic models (rebuilt from their import path with `model_validate`), and dataclasses made of those. A step whose output cannot be stored exactly is executed live during replay, and the replay summary lists it. Loading pickles from a project folder would let a planted file run code, so Tervic never does it.
- **Where replay works.** Plain Python `@tervic.step` pipelines and LangGraph (node functions are wrapped, so recorded node outputs can be served) replay from any step. For the OpenAI Agents SDK and CrewAI, Tervic cannot substitute an agent's internal steps, so replay means `--offline`: the entry point is re-run and every LLM call made through a client wrapped with `tervic.attach_llm` is served from the cassette.
- **Entry point input.** `tervic.run(..., input=...)` and LangGraph `invoke(input)` record the run input exactly when possible; replay calls the entry point with that input (or with no arguments if none was recorded).
